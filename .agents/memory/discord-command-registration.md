---
name: Discord command registration
description: Published Botの機能がDiscordのコマンド一覧に出ないときの運用上の注意
---

**Rule:** Botのコードを公開しても、Discord側のスラッシュコマンド定義が自動的に更新されるとは限らない。コマンド名やサブコマンドが存在しても、その中のオプションだけが古い場合がある。変更時はネストしたオプションまで確認し、特定コマンドだけの変更なら個別upsertを優先して全件置換を避ける。

**Why:** 新しいカジノサブコマンドのコードは存在したが、Discordに残っていた定義は古く、ユーザーからはコマンドが見えなかった。全件置換を使うと、独立して同期されるサーバー専用コマンドが消えるおそれがある。

**How to apply:** コマンドや選択肢が見つからない報告では、まずDiscordのグローバル・サーバー両方の登録内容を、サブコマンド内の選択肢までコードと照合する。必要な定義のみをDiscord APIで更新し、更新後に両スコープを読み直す。Bot本体が新コードで動いているかは登録とは別に確認する。

**Verification caveat:** discord.js では ID 指定のコマンド取得は既定でキャッシュを返す。更新直後の検証でこれを使うと、Discord側の再取得をしたつもりでもローカル結果だけを確認してしまう。**Why:** 更新APIの戻り値だけでは実際の登録状態を独立に確かめられない。**How to apply:** 個別コマンドを読み直すときはキャッシュを強制的に無視して取得する。

**Comparison caveat:** discord.js のビルダーJSONには未指定でも `nsfw: undefined` が残り、取得済みコマンドでは既定値が `false` になる。素の `equals()` はこの差を不一致扱いする。**Why:** 正常な登録でも起動ごとに再更新し、成功後の検証まで失敗する。**How to apply:** 比較用の定義では既定値を正規化し、スコープによって補完される未指定の contexts/integration types を考慮する。実物のビルダーJSONとDiscordのコマンドオブジェクトを使って検証する。

**REST omission caveat:** Discordの取得結果はオプションの `required: false` や空の `options: []` を省略する場合がある。**Why:** ビルダーの明示的な既定値とそのまま比較すると、正常な更新も検証失敗に見える。**How to apply:** 省略と同等の既定値だけ正規化し、サブコマンド名・順序・必須指定・制限値の実際の相違は引き続き検出する。

**Scope policy:** 懸賞金対象サーバーでは、同名・同種類のグローバル登録が存在する場合はそちらを利用し、重複するギルド登録は削除する。グローバル登録がないサーバー専用コマンドは維持し、他サーバーへこの方針を自動的に広げない。

**Why:** ユーザーは「ギルドコマンド全件削除」ではなく「グローバルと重複するものだけ」を選択した。サーバー専用コマンドを失わせたり、Bot再起動で重複を復活させたりしないため。

**How to apply:** 対象サーバーでの同期・手動登録もこの方針を守る。削除は実際のグローバル登録との名前・種類の一致で判定し、全件置換ではなく個別削除後にDiscordから読み直して検証する。

**External weapon Bot:** ユーザーによると、武器BOTのコードはConoHa VPSに置いている。

**Why:** このワークスペースに武器コマンドの定義がなくても、外部の登録処理が同じDiscordアプリのコマンド一覧を変更する可能性がある。配置場所だけでトークン共有を断定しない。

**How to apply:** 武器コマンドによる銀行コマンドの置換を調査する際は、VPS側の利用アプリIDと登録方式を秘密値を表示せず確認する。ワークスペースの設定確認だけでVPSも確認済みと報告しない。

**Bank command policy:** 銀行Botでは `/give`（管理者専用）、`/guide`、`/leavelog`、`/roulette` を登録・利用可能にする。これらを起動時やデプロイ時に自動削除しない。

**Why:** 以前の削除依頼をユーザーが撤回し、銀行Botのコマンドを元に戻すよう依頼した。

**How to apply:** `/give` は管理者専用の通貨付与を維持する。送金・残高・カジノを含む既存コマンドを維持し、戻すコマンドは個別upsertで登録する。全件置換や起動時削除を行わず、データや既存設定も変更しない。
