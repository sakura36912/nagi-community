# 武器・ボス機能の多機能Botへの移管

武器11コマンドとボス8コマンドを銀行Botから多機能Botへ移管する。通貨・武器・強化設定・開催中の戦闘は同じDBを使い、移行や初期化をしない。本船員・管理者の既存の利用資格、内部数値の非公開、料金・報酬規則も変えない。銀行以外のアプリの定義やショップ・カジノなどは削除しない。

## 反映

両Botの新コードを反映・再起動する。このReplitの本番起動スクリプトは両Botを起動する。開発環境でBotを追加起動して二重稼働させない。VPSへの反映は別作業。

1. 多機能Botが追加テーブルの存在を確認し、期限復旧・結果再送を開始する。
2. 多機能Botのアプリに武器・ボス19件を個別登録する。他の定義は全件置換しない。
3. 銀行Botは多機能BotのアプリID、19件の登録をRESTで確認する。
4. 確認できた場合のみ、銀行Botのグローバル・参加サーバーのギルド登録から対象19件と旧英語12件を個別削除する。同名のコンテキストメニューは対象外。
5. 起動順・接続障害で確認できなければ削除を保留し、60秒後に再確認する。後からサーバーに参加した場合も再確認する。

削除確認には銀行Botの実行環境にも `COMMUNITY_BOT_TOKEN` が必要。このReplitでは既存の共有Secretを使い、値をログへ出さない。`COMMUNITY_CLIENT_ID` が設定されている場合はアプリIDの一致も確認する。別のBotのトークンやIDの場合は削除しない。

移管は銀行Botの全参加サーバーに適用する。多機能Botが未参加のサーバーでも銀行側の対象定義は削除するため、そこで利用を続けるには多機能Botを招待する。各サーバーで多機能Botにコマンド利用・チャンネル閲覧・メッセージ送信・埋め込み表示の権限が必要。

## 旧メッセージ

Discordでは銀行Botが作成した古いメッセージのボタンは銀行Botへ届くため、多機能Botへ付け替えたとは扱わない。古いボタンやキャッシュされた銀行コマンドには非公開の移管案内を返し、銀行側では課金・強化・戦闘操作をしない。利用者は多機能Botの同名コマンドを実行する。

既存の戦闘はID・参加者・残りHP・期限を引き継ぐ。移管前に送信済みの通知は送り直さず、未送信の終了通知は多機能Botが既存の配送記録に従って送る。新しいBotが投稿先を閲覧できない場合は再送待ちになるため、チャンネル権限を直す。

反映前には実際のDiscord登録・本番データを変更しない。開発用の合成データとモックDiscord APIで権限・支払い・登録/削除範囲を検証する。
