# JSONデータベースバックアップ

## 本番：Discord

再公開後、Botアプリケーション所有者が管理者権限を持つサーバーで
`/backup export` を実行し、本人だけに表示される確認ボタンを押します。
チーム所有アプリではチーム所有者のみ実行できます。通常のサーバー管理者や
チームメンバーには全サーバー分のデータを渡しません。

実行中のBotの `DATABASE_URL` に接続します。公開中のBotなら本番DBが対象です。
確認ボタンでも所有者を再確認し、同時実行は1件までです。
添付は本人だけに表示し、ローカルの一時ファイルは送信後・失敗時に削除します。

## 開発：Replit Shell

リポジトリのルートで実行します。BotのGateway接続は起動しません。

```sh
pnpm --filter @workspace/discord-bot backup:export
```

保存先は `generated-artifacts/database-backups/database-backup-*` です。
このディレクトリはGit・公開イメージから除外しています。保存先の変更：

```sh
pnpm --filter @workspace/discord-bot backup:export --output /tmp/my-private-backups
```

現在のShell環境の `DATABASE_URL` が対象です。開発DBと本番DBは別なので、
開発Shellで実行しても本番DBのバックアップにはなりません。
接続先URLや認証情報をログ・JSONへ書き出しません。

## ファイルと対象範囲

- `manifest.json`：バックアップID、スナップショット日時、テーブル・列情報、
  行数、全データファイルの一覧・サイズ・SHA-256。
- `data-*.json`：実データ。各ファイルは独立した有効なJSONです。
  Discord用は1ファイル7MiB以下に分割します。Shell用は原則1データファイルです。
- **manifestとすべてのデータファイルをセットで保管してください。**
  複数に分かれた同一テーブルは `rowOffset` の順に連結して扱います。
- 同じ読み取り専用・REPEATABLE READトランザクションで、全ユーザー・全サーバーの
  非システムスキーマにある通常テーブル、パーティションルート、マテリアライズドビューを
  書き出します。空テーブルも含みます。RLSで一部の行しか読めない場合は失敗扱いにします。
- PostgreSQLが直接生成したJSONを保存するため、大きな整数・小数の桁を
  JavaScriptの数値変換で丸めません。将来インポートする際もlossless JSONパーサーが必要です。
- DB外の画像・音声などのファイル本体、環境変数・シークレット、
  DBロール、インデックス、トリガー等の完全なDDLは対象外です。
  DB内に保存された外部ファイルの参照先は含みます。
- これは**データのエクスポート機能**です。DBへ上書きする復元機能はありません。

個人情報・金融的な履歴を含みます。ファイルを公開リポジトリや公開チャンネルに
置かず、取得後は安全な保存先へ移してください。バックアップ用ディレクトリは0700、
JSONファイルは0600で作成します。

接続待ちは10秒、個別SQLは60秒、全体は原則5分までです。実行失敗時は未完成の
ローカル出力を削除し、完全なバックアップとして扱いません。Discordの送信途中に
失敗した場合も完了とは表示しません。単一レコードが7MiBの分割上限を超える場合は
省略せず失敗します。Shell版はこの分割上限がありません。
