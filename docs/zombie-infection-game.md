# 多機能Bot：Halloween ゾンビ感染ゲーム

## 決定済みのルール

- 治療班は感染しない。勝敗判定の「全員」から除外する。
- 報酬は銀行Botと共通のサーバー別残高へ加算する。別財布や外部APIは作らない。
- 設定済み酒場VCで連続3分以上同席し、実際の会話を管理者が確認して承認する。
- 録音・音声認識はしない。無言、挨拶だけ、テキストやリアクションは承認しない。
- 役職はDiscordの公開ロールではなくDB内部に保存し、本人DMと管理者限定の表示だけで扱う。

## 最初の設定

Administrator権限のある管理者が操作する。
公開用の「告知」「ルール」「結果」、非公開の「管理」「感染ログ」「役職管理」を
通常のテキストチャンネルとして用意する。管理用3つは別チャンネルにする。
公開用と管理用の共用は禁止。

管理用は一般メンバーに閲覧を許可せず、管理者とこのBotだけが閲覧できるよう設定する。
Botには閲覧・送信・埋め込み権限が必要。
設定時、開始時、秘密情報の送信直前に、チャンネルとロール／個人の閲覧権限を再確認する。
公開状態になった管理チャンネルには秘密の通知を送信しない。

```
/zombie config 告知:#イベント告知 ルール:#ルール説明 結果:#結果発表 管理:#イベント管理 感染ログ:#感染ログ 役職管理:#役職管理
/zombie vc
/zombie exclude 除外:True ユーザー:対象者
/zombie exclude 除外:True ロール:除外ロール
```

除外の解除はFalse。ユーザー／ロールは一度にどちらか1つを指定する。
`/zombie vc` をオプションなしで実行すると、本人だけに見えるVC複数選択メニューが開く。通常のVCを最大25件まとめて選び、確定すると対象VC一覧を置き換える。0件を選ぶと全解除。操作時にも管理者資格を確認し、本人専用・15分有効とする。

既存の指定は選択済みで表示する（削除済みのVCは除く）。従来の `/zombie vc 対象:大酒場 有効:True` による1件ずつの追加・解除も維持する。25件を超える設定は従来の個別操作で扱えるが、メニューで保存すると最大25件になる旨を表示する。

VC・除外・チャンネル設定の変更は次回のイベントに適用する。開催中のVC対象・参加者・同席判定は変更しない。
サーバーの既存コマンド利用制限も維持される。

## 報酬の設定

```
/zombie rewards
/zombie rewards 項目:人間：生存報酬 金額:管理者指定額
```

7項目すべてを設定してからゲームを開始する。未設定と無料の0は区別する。
準備中に変更した報酬はbeginで取り込む。開始後の報酬は固定。
1人あたりの報酬合計が整数上限を超える設定は開始前に拒否する。

| 項目 | 対象 |
| --- | --- |
| 人間：生存報酬 | 終了時に人間の参加者 |
| 人間：勝利報酬 | 人間陣営勝利時、終了時に人間の参加者 |
| 人間：未感染ボーナス | 終了時に人間かつ一度も感染していない参加者 |
| ゾンビ：勝利報酬 | ゾンビ陣営勝利時、終了時にゾンビの参加者 |
| ゾンビ：最多感染ボーナス | 終了時のゾンビのうち、感染人数が最多かつ1人以上。勝敗にかかわらず、同率なら各人へ満額 |
| 治療班：協力報酬 | 治療班の参加者。勝敗にかかわらず配布 |
| 治療班：治療人数1人あたり | 治療班の治療人数を掛けて加算 |

感染人数・治療人数は、承認が成立した**別々の相手の人数**。
同じ相手との再感染・再治療で人数を水増ししない。
治療後も「一度感染した」という履歴は残り、未感染ボーナスは復活しない。

## 開催手順

1. 参加者に対象VCへ集合してもらう。
2. `/zombie start` で、その時点の対象VCのメンバーを登録し、初期役職をランダム抽選する。省略時はゾンビ1人・治療班2人。`/zombie start ゾンビ数:2 治療班数:3` のように人数を変更できる。
3. Bot、設定した除外ユーザー・ロール、VC記録をオプトアウトした人は除外する。
4. ゾンビと治療班は参加者から重複なしで自動選出し、残りを人間にする。人間を最低1人残すため、既定値では対象者4人以上が必要。人数不足・不正な指定ではイベントを作成せずDMも送らない。
5. 本人DMと管理者限定ログで役職を通知する。管理者は `/zombie status` で確認できる。開始コマンドの同じ処理を再実行しても再抽選・DMの二重作成はしない。
6. 必要な場合だけ、準備中に `/zombie set_zombie`・`set_healer`・`set_human` の対象指定で手動修正できる。通常は手動設定不要。
7. `/zombie begin` でゲーム開始。告知・ルールを送信する。

start時点では初期役職の抽選済み・開始待ちであり、感染申請はまだできない。begin時に再抽選しない。既存の準備中・開催中イベントは、この変更の公開やBot再起動だけでは再抽選しない。
最初のゾンビと、治療班以外の人間が各1人以上必要。
役職の手動設定は準備中だけ可能。準備中・開催中に対象VCへ入った未登録メンバーは、人間として自動参加する。Bot、除外ユーザー・ロール、VC記録拒否者は追加しない。参加条件は開催中イベントに保存された設定を使用する。

入室イベントに加え、Bot起動時と15秒間隔でも在室者を確認するため、再起動時に対象VCにいる未登録者も追加する。Bot停止中に入退室を完了した人や、過去の同席時間は推定しない。ミュート中でも参加者には登録するが、感染・治療の同席時間は数えない。

参加時に本人へDM、管理者限定チャンネルへ記録を送る。DM失敗は再送対象。退出しても登録を削除せず、再入室時に役職・感染歴・感染／治療人数をリセットしない。途中参加者も通常の勝敗・報酬対象とし、最低参加時間による減額や日割りはしない。

全員感染または管理終了で精算済みのイベントは、後からの入室で再開・再精算しない。報酬の整数上限を超える人数増加になる場合は参加を保留して管理者に通知する（既存参加者の残高は変更しない）。
サーバーごとに準備中／開催中のイベントは1つ。

役職設定・感染・治療のDMは送信キューに保存して再試行する。
DMを拒否している場合でも `/zombie me` で自分の役職を本人限定で確認できる。
島民ロール所持者は `/zombie`・`/infect`・`/heal` 共通のロール制限を通過できる（追放者の制限は維持）。`/zombie me` は本人限定表示。感染・治療申請はゲーム内の役職・参加状態・同席時間・クールタイムを引き続き検証する。開始・終了・設定・全員の役職一覧・申請の承認と却下などの管理操作は、島民ロールの有無にかかわらず実際の管理者権限が必要。未参加の場合は自分の役職を表示しない。
古い役職DMは役職バージョンが変わったら送らない。
終了後に届く現役職のDMには「終了済みイベントの通知」と明記する。

## 感染・治療・承認

```
/infect request 対象:ユーザー
/heal request 対象:ユーザー
```

Discordでは1つのスラッシュコマンドに、直下のユーザー引数とaccept等のサブコマンドを
混在できないため、申請はrequestサブコマンドに統一する。

- 感染申請はゾンビ、治療申請は治療班だけ可能。
- 自分自身や未登録ユーザーへは申請不可。
- 設定済み酒場VCで連続180秒以上同席している必要がある。
- VC移動、退出、ミュート・スピーカーミュート、Bot再起動・再接続・観測失敗後は数え直す。
- ゲーム開始・役職変更前の同席時間を、新しい役職の申請に流用しない。
- 停止中の時間は推測加算しない。
- Botが保存するのはVCと同席開始時刻、申請時の同席秒数。会話内容は保存しない。

申請は管理チャンネルへ届く。
管理者は実際の会話を確認して「会話を確認して承認」または「却下」を押す。
コマンドからも操作可能：

```
/infect accept 申請:申請ID
/infect reject 申請:申請ID
/heal accept 申請:申請ID
/heal reject 申請:申請ID
/zombie requests ページ:1
```

申請の有効期限は15分。同じ相手・種類の同時申請は1件、1人の承認待ちは最大10件。
申請後にVCを離れても、提出時点の同席証拠について管理者が審査できる。
承認時にはイベント・申請・役職・役職変更履歴を再確認する。
古い申請、すでに感染／治療された対象、治療班への感染は成立させない。
申請者への不成立通知では、対象者が治療班かどうかを開示しない。
承認結果と実行者は非公開の感染ログへ記録する。
承認ボタンは古いものも含め、毎回Administrator権限をライブ取得して確認する。

## 状態・終了

```
/zombie me
/zombie status ページ:1
/zombie end 確認:True
/zombie cancel 確認:True
```

me以外は管理者限定。statusは5人ずつ、役職・感染人数・治療人数・未送信通知を表示。
本人表示・申請・管理コマンドの返答はすべて非公開。

- 治療班以外が全員ゾンビになると自動で勝敗を確定して精算する。
- 管理者がendしたとき、人間が1人でも残っていれば人間陣営の勝利。
- cancelは準備中・開催中の中止用であり、報酬を配布しない。
- 終了日時の予約は今回未追加。人間側の終了時刻は管理者がendで管理する。

報酬、銀行残高、台帳、終了状態は同じDBトランザクションで確定。
誰かの残高上限や台帳書込みに問題があれば全員分を取り消す。
自動終了であれば、その最後の感染承認も取り消す。
問題を解消して再実行するまで成功通知は送らない。
同じ承認や終了を再受信しても、二重感染・二重報酬にしない。
終了操作の処理記録は次回イベントが始まっても残し、旧操作で新イベントを終了させない。

公開の結果には勝利陣営と参加人数だけを出し、役職一覧・個人の感染履歴・治療班を公開しない。
個人の加算額は本人DMで通知する。

## バランス調整

### Hub転送先VC

対象として設定したHubに紐づく生成VCも、開始時の参加者取得・途中参加・感染・治療・能力移譲の判定対象にする。開催中に作られた転送先も自動で検出する。開催中に設定VCを変えても元設定のスナップショットは維持する。

同じサーバーのHub設定と転送先セッション記録が一致したVCだけを含める。panel-only（別Botが管理する転送先）も対応記録があれば対象だが、この機能はVCを作成・削除しない。名前やカテゴリが同じだけのVCや、由来が記録されていない外部BotのVCは自動判定しない。

同席証拠・誤治療の引き戻し先は実際の転送先VCのIDで保持する。別々の転送先にいる人の時間を合算せず、VCを移動したら連続3分を数え直す。対応記録が削除されたVCは次回照合で対象外になり、承認待ち申請の対象VCも再検証する。対応のDB照合に失敗した場合は同席時間を引き継がず、復旧後に数え直す。

- 治療成立時から60秒間、治療班は新しい `/heal request` を申請できない。既に保留中の治療申請も、クールタイム中は承認できない。再実行で期限は延長しない。残り時間はエラーと `/zombie me` で本人に表示する。
- 人間への治療申請は「誤治療」として扱う。通常と同じ連続3分・会話確認・管理承認を必要とし、承認前・却下・期限切れでは制限しない。承認時点でも対象が同じ人間状態であることを確認する。
- 誤治療の対象者は承認から60秒間、別のVCへ移動すると元のVCへ引き戻される。Botには元VCの閲覧・接続・メンバー移動と、移動先のメンバー移動権限が必要。切断は妨げず、切断した人を強制的に再接続しない。チャンネル権限やロールは変更しない。
- 期限終了・終了・中止で引き戻しを停止し、非公開の感染ログへ開始・解除を記録する。権限不足・VC削除などの失敗は同ログへ記録し、期限内は再試行する。Bot停止中には移動を戻せないが、再起動後はDBの期限を参照するため期限を延長しない。
- 治療班とゾンビ2人以上が指定酒場VCで連続180秒同席すると、自動で能力移譲する。この処理だけは管理承認不要で、実際の会話の有無は自動判定しない。ミュート・退出・VC移動・役職変更・Bot再接続で必要な連続時間を数え直す。
- 元治療班は人間になり、その時点で人間である別の参加者1人を暗号学的乱数で選んで新治療班にする。同じ判定中に能力を失った人への即時再移譲はしない。移譲先がいなければ能力を維持して保留し、非公開ログへ記録する。
- 移譲に関連する承認待ち申請は無効化する。感染歴・既存の人数実績はリセットせず、報酬の陣営区分は従来どおり終了時の役職で判定する。本人2名への秘密DMと非公開の役職ログを、状態変更と同じDBトランザクションで保存する。
- クールタイム・移動制限は絶対日時で保存する。Bot停止中の同席時間は能力移譲に加算しない。公開ルールに仕様を表示するが、対象者や秘密役職の一覧は公開しない。

## 保存・反映・検証

既存PostgreSQLに追加専用で以下を作成する。既存残高やVC記録を削除・変換しない。

- zombie_configs：サーバー設定
- zombie_games：参加者・役職・感染履歴・同席証拠・申請・勝敗・報酬
- zombie_jobs：永続通知キュー
- zombie_operations：終了・中止操作の処理記録

通知は15秒ごとに処理し、失敗時は1分後から再試行する。
役職DMが拒否されている場合やログチャンネルが削除された場合はstatusに未送信が残る。
通知の再送は決済を再実行しない。Discord nonceとDBの送信排他制御を併用する。
履歴は明示削除・保持期限機能を追加するまではDBに保持する。

多機能Botのコードを再公開・起動すると、zombie / infect / healの3コマンドを個別登録する。
銀行Botの同名コマンドやサーバー専用コマンドを削除・全件置換しない。
開発と本番で同じBotを重複起動しない。今回の作業では本番更新・実イベント開催は行わない。

```sh
RUN_ZOMBIE_DB_TESTS=1 pnpm --filter @workspace/community-bot exec vitest run src/__tests__/zombie-db.test.ts
pnpm --filter @workspace/community-bot exec vitest run src/__tests__/zombie-interaction.test.ts
```

DBテストは開発DBの合成ユーザー・合成サーバーだけを使い、終了時に削除する。
