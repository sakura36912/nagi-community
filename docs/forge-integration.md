# カードからの連続強化

新しい武器選択・強化結果の公開カードに、所有者本人専用の「次の強化」ボタンを表示します。
押すたびに非公開で新しい費用・成功率の確認を作成し、「支払って強化」で1回分を確定します。
決済結果の非公開返信にも次回確認ボタンがあり、コマンドの再入力は不要です。
成功・失敗とも同じ導線で続行でき、他人の操作、ロール剥奪後の利用、古い確認の二重決済は許可しません。
既に送信済みの古い公開カードへは自動でボタンを追加しません。

# 多機能Bot：武器・鍛冶屋（銀行残高共有）

## 実行構成

多機能Bot（TypeScript / discord.js）で操作し、既存の銀行Botと同じPostgreSQLの残高・武器データを使う。
Python製の別Bot・SQLite・外部銀行APIは追加しない。
本機能の強化代は既存の `wallets` の同一サーバー・同一ユーザーの残高から直接引く。
VPS側の旧鍛冶屋BotやSQLiteデータは変更・自動移行していない。

## コマンド

一般向けは、名前が完全一致する「本船員」ロール所持者のみ。
ロール未作成・同名ロール複数の場合は利用を止める。
管理者権限だけでは一般向けコマンドの本船員チェックを迂回できない。

| コマンド | 機能 |
| --- | --- |
| `/武器選択 種類` | 大剣・片手剣・槍・弓・双剣・杖から一度だけ選択 |
| `/武器` | 武器名、Lv、スキル名、次回強化費用、成功率（本人向け非公開応答） |
| `/強化` | 2分間有効な支払い確認。確定するまで課金しない |
| `/強化費用確認 ページ` | 料金と成功率の一覧 |

以下は **Administrator** が必要（ManageGuildのみでは不可）。

| コマンド | 機能 |
| --- | --- |
| `/武器変更 ユーザー 種類 確認:True` | レベルを維持して武器種を変更し、内部数値を再計算 |
| `/武器リセット ユーザー 確認:True` | 武器を削除。再選択可。残高変更・返金なし |
| `/武器確認 ユーザー` | 内部攻撃力・防御力も表示（管理者向け非公開応答） |
| `/強化費用設定 レベル 金額` | 強化前レベルの費用を設定。0は明示的な無料 |
| `/強化成功率設定 レベル 確率` | 強化前レベルの成功率（整数30〜100%） |
| `/強化費用リセット 確認:True` | 料金のみ初期化。成功率を維持 |
| `/強化成功率リセット 確認:True` | 成功率のみ初期化。料金を維持 |

すべてサーバー内専用。メンバーを操作時に再取得し、権限・本船員ロールを検証する。
一般向け表示に攻撃力・防御力・内部ステータスを含めない。

## 初期設定・内部バランス

- 初期費用は仕様書の例を採用：Lv1→2 $1,000、Lv2→3 $3,000、Lv3→4 $5,000。
- Lv4以降の費用は未設定。管理者の設定前には強化できない。リセット後も同様。
- 初期成功率：`max(30, 100 - (強化前Lv - 1) * 5)`。
- 内部ステータスは武器別基礎値と成長量で算出（`forgeRules` に集約）。
  元のPython Botの数値が未提供のため、その再現ではなく初期プロファイル。
- 成功時はレベル・攻撃力・防御力が上昇。
- 失敗時も費用を消費。レベル・攻撃力・防御力は下がらず、武器も破壊されない。
- 素材は使用しない。武器種変更は管理者のみ。
- 固有スキル名は保存・表示する。統合版ボス戦の発動・回復等の効果は
  [ボス討伐の仕様](boss-events.md)で定義する。

## 安全な決済・永続化

追加するテーブル：`forge_weapons`、`forge_upgrade_settings`、
`forge_upgrade_requests`、`forge_actions`。既存テーブルの再作成や削除はしない。
武器は `(guild_id, user_id)` を複合主キーとする。
起動時・初回操作時に冪等な追加専用マイグレーションを実行する。

確認パネルと処理済み記録をDBへ保存するため、Bot再起動後も
有効期限内の確認・二重課金防止を維持できる。
ロール剥奪、他ユーザー・他サーバーの操作、期限切れ、キャンセル、
武器の変更、費用・成功率の変更があった確認は課金せず拒否する。
管理者の武器変更・リセットは古い確認パネルも無効化する。

武器と設定の排他制御、残高の条件付き減算、武器更新、取引台帳、
処理済み記録は同じDBトランザクションで扱う。
一部の書き込みが失敗したらすべてロールバックする。
同じボタンの再押下は保存済み結果を返し、再課金・再抽選しない。
失敗した強化でも武器バージョンを進め、古い別パネルでの連続決済を防ぐ。

## ボス連携口・拡張

統合版のボス討伐は `boss-events.md` に記載した機能として追加。
既存のVPSボスや旧SQLiteには接続・移行していない。
銀行Botを外部HTTP APIとして公開する変更はしない。

- `getForgeCombatant(guildId, userId)`：内部武器データを取得。
- `calculateForgeDamage(weapon, options)`：攻撃力、武器別・Lv別の成長結果、
  ロール倍率、0.9〜1.1の乱数補正、クリティカル補正からダメージを計算。
- 呼び出し側が参加資格・対象サーバー・ロール補正の根拠を検証する。
- デフォルトのクリティカル率10%、倍率1.5は内部初期値。関数引数で変更可能。
- 統合版ボスは同じ武器テーブルから、攻撃時に同じ武器の最新Lv・攻撃力を読み直す。
  強化は参加中の討伐にも次の攻撃から反映される。参加時の武器種類・防御力・ロール倍率・最大HPは固定する。
  武器Lv補正・スキル・ロール・ボス防御力を含む戦闘計算を維持する。
- 覚醒、限界突破、スキン、PvP、ガチャ等は今後の拡張であり未実装。

## 反映・確認

本番への反映には、変更済みコードでBotを再起動／再公開する必要がある。
新コードの起動後、日本語の鍛冶屋コマンド11件だけをDiscordへ個別登録する。
他の銀行・多機能・サーバー専用コマンドは全件置換しない。
旧英語コマンドを登録するVPSプロセスが残っている場合は別途修正が必要。
同じ銀行トークンを使うBotを複数環境で同時起動しない。

開発用DBテスト（合成データは終了時に削除）：

```sh
RUN_FORGE_DB_TESTS=1 pnpm --filter @workspace/community-bot exec vitest run \
  src/__tests__/forge-db.test.ts
```

通常のルール・操作テスト：

```sh
pnpm --filter @workspace/community-bot exec vitest run \
  src/__tests__/forge-rules.test.ts src/__tests__/forge-interaction.test.ts
```
