# 多機能Bot：ペット育成（初期版）

## 方針

- サーバー内で1人1匹。卵・エサは複数保管できます。ペットは必ず卵から即時孵化します。
- レア・エピック・レジェンド・ミシックは各10種類、指定の計40種類。卵のレアリティ内は同確率です。
- ノーマル種は未指定のため、管理者が種類を登録するまでノーマル卵の販売・孵化はできません。
- 価格と育成数値には仮の値を入れていません。必要項目が未設定なら対象の購入・お世話・経験値付与を停止し、エサや残高は消費しません。
- 初期Lv1、満腹度100、親密度0。レベル上限は初期100、管理者が1～100に変更できます。既存ペットのレベルは下げません。
- スキル・進化・性格・個体値・装備・対戦・マーケット・交配・ランキング・称号・専用クエスト・覚醒・遠征・図鑑は実装していません。

## 一般コマンド

| コマンド | 内容 |
|---|---|
| `/pet info` | ペットカード、個体ID、誕生日、今日のお世話回数 |
| `/pet inventory` | 全レアリティの卵、エサの在庫 |
| `/pet hatch egg:` | 所持卵の種類を選び即時孵化。既にペットがいれば卵を消費せず拒否 |
| `/pet feed` | エサ1個を消費し満腹度・経験値・親密度を付与 |
| `/pet pet` | 日本時間の1日1回、親密度のみ付与 |
| `/pet play` | 日本時間の1日3回、経験値・親密度を付与 |
| `/pet shop` | 価格・販売停止状態 |
| `/pet buy item: quantity:` | ノーマル卵・レア卵・エサの購入確認。2分以内に本人が「支払って購入」 |
| `/pet release` | 2分以内に本人が確認して手放す。育成データは復元不可、卵・エサは維持 |
| `/pet settings` | 育成設定の確認 |

状態確認・購入確認・管理操作の返答は本人限定です。銀行Botと同じサーバー・ユーザーのウォレットから「$」を引き落とします。購入・在庫増加・銀行取引記録・重複防止記録は同じトランザクションです。価格変更後の古い購入確認は課金せず拒否します。キャンセルと購入確定が同時に届いても、先に確定した一方だけが有効です。

## 管理者コマンド

実行時にサーバーのAdministrator権限を再取得します。一般コマンドの利用者に管理権限は広げません。

| コマンド | 内容 |
|---|---|
| `/pet grant user: rarity:` | ペット配布を**卵1個**として実施。直接ペットを上書きしない |
| `/pet egg user: rarity: quantity:` | 卵配布（5レアリティ） |
| `/pet food user: quantity:` | エサ配布 |
| `/pet delete user:` | 確認後に対象のペットを削除。確認時にも管理権限と個体IDを検証 |
| `/pet price item: amount:` | ショップ単価。0を明示設定した場合だけ無料 |
| `/pet config key: value:` | 下記の育成数値・必要経験値・倍率・上限を設定 |
| `/pet species rarity: names:` | 種類を「、」区切りで設定（1～25種、各40文字以内）。既存の個体は変更しない |
| `/pet reward user: reference: item: quantity:` | 管理者がイベント報酬・クエスト達成を登録し卵・エサ・経験値を付与 |

報酬の`reference`は、イベント・クエストの達成を識別する管理用の記録IDです。同じサーバー・対象者・記録IDでは重複付与しません。別の報酬を追加する場合は別の記録IDを使ってください。経験値報酬には設定済みの経験値倍率を適用し、対象者にペットがいない場合は未配布としてエラーにします。既存のボス・ゾンビなどへ自動的に報酬を追加する変更はありません。

### 管理者が設定する数値

`/pet config` の `key` 選択肢に説明が表示されます。

| key | 意味 |
|---|---|
| `xp_base` | 次レベルの必要経験値＝この値×現在レベル |
| `xp_multiplier` | 獲得経験値の倍率（0～100、小数可、端数切り捨て） |
| `level_cap` | レベル上限（1～100、未設定時100） |
| `message_xp` / `message_interval` | メッセージ1件の基礎経験値／獲得間隔の秒数 |
| `vc_xp` / `vc_interval` | VCの基礎経験値／獲得間隔の秒数 |
| `hunger_interval` / `hunger_loss` | 満腹度が減る間隔の秒数／1間隔で減る量 |
| `feed_hunger` / `feed_xp` / `feed_bond` | エサ1個による満腹度・基礎経験値・親密度 |
| `pet_bond` | 撫でたときの親密度 |
| `play_xp` / `play_bond` | 遊んだときの基礎経験値・親密度 |

必要経験値の基準と時間間隔は1以上の整数です。親密度・満腹度の増減設定は0～100、育成後の値も0～100です。満腹度0は「空腹」表示のみで、死亡や能力低下はありません。時間経過は取得時に計算し、Bot停止中も満腹度は減ります。設定を変える時点まで旧設定で精算するため、新設定を過去へ遡って適用しません。

### VC・メッセージ経験値

- サーバー内のBot・Webhook以外のメッセージを対象に、設定した獲得間隔で付与します。本文の読み取り・保存はしません。追加するGateway Intentは`GuildMessages`のみで、`MessageContent`は不要です。
- VC経験値は全VC・ステージVC（Hub生成先を含む）で、Botが接続中に観測した時間にだけ付与します。VC記録のサーバー別／全体オプトアウトを尊重します。
- VC退出直前の観測を精算します。獲得間隔に満たない観測済みの時間は在庫データに保持し、移動・再入室・再起動でも引き継ぎます。
- 切断・停止時間や90秒超の観測欠落は推定加算しません。接続復旧後から観測を再開します。
- 孵化前の活動は遡って経験値にしません。ペットを手放すとその個体の経験値と活動の途中経過も破棄します。

## 保存・公開

`pet_settings`・`pet_accounts`・`pet_actions`で設定、個体、在庫、日次回数、活動の最終観測、操作記録をPostgreSQLに保存します。個体IDはUUID、オーナーとサーバーはアカウント主キーです。同時操作もアカウントごとのロックで直列化します。

開発DBへ3テーブルを追加済みです。本番へは通常の再公開でスキーマを適用してください。起動時DDLや本番マイグレーション用スクリプトは追加していません。多機能Bot起動時に `/pet` のグローバル定義だけを個別更新し、他のコマンドとギルド専用コマンドは置換しません。本番と同じトークンで開発Botを二重起動していません。
