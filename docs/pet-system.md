# 多機能Bot：ペット育成（初期版）

## 方針

- サーバー内で1人1匹。卵・エサは複数保管できます。ペットは必ず卵から即時孵化します。
- レア・エピック・レジェンド・ミシックは各10種類、指定の計40種類。卵のレアリティ内は同確率です。
- ノーマル種は未指定のため、管理者が種類を登録するまでノーマル卵の販売・孵化はできません。
- 価格と育成数値には仮の値を入れていません。必要項目が未設定なら対象の購入・お世話・経験値付与・治療を停止し、エサ・おもちゃや残高は消費しません。
- 初期Lv1、満腹度100、親密度0。レベル上限は初期100、管理者が1～100に変更できます。既存ペットのレベルは下げません。
- スキル・進化・性格・個体値・装備・対戦・マーケット・交配・ランキング・称号・専用クエスト・覚醒・遠征・図鑑は実装していません。

## 一般コマンド

| コマンド | 内容 |
|---|---|
| `/pet info` | ペットカード、個体ID、誕生日、今日のお世話回数 |
| `/pet inventory` | 全レアリティの卵、エサ・おもちゃの在庫 |
| `/pet hatch egg:` | 所持卵の種類を選び即時孵化。既にペットがいれば卵を消費せず拒否 |
| `/pet feed` | エサ1個を消費し満腹度・経験値・親密度を付与 |
| `/pet pet` | 日本時間の1日1回、親密度のみ付与 |
| `/pet play` | おもちゃ1個を消費。日本時間の1日3回、経験値・親密度を付与 |
| `/pet shop` | 価格・販売停止状態 |
| `/pet buy item: quantity:` | ノーマル卵・レア卵・エサ・おもちゃの購入確認。2分以内に本人が「支払って購入」 |
| `/pet release` | 2分以内に本人が確認して手放す。育成データは復元不可、卵・エサ・おもちゃは維持 |
| `/pet settings` | 育成設定の確認 |

状態確認・購入確認・管理操作の返答は本人限定です。銀行Botと同じサーバー・ユーザーのウォレットから「$」を引き落とします。購入・在庫増加・銀行取引記録・重複防止記録は同じトランザクションです。価格変更後の古い購入確認は課金せず拒否します。キャンセルと購入確定が同時に届いても、先に確定した一方だけが有効です。

## 管理者コマンド

実行時にサーバーのAdministrator権限を再取得します。一般コマンドの利用者に管理権限は広げません。

| コマンド | 内容 |
|---|---|
| `/pet grant user: rarity:` | ペット配布を**卵1個**として実施。直接ペットを上書きしない |
| `/pet egg user: rarity: quantity:` | 卵配布（5レアリティ） |
| `/pet food user: quantity:` | エサ配布 |
| `/pet panel` | このチャンネルに卵・エサ・おもちゃのショップパネルを設置 |
| `/pet delete user:` | 確認後に対象のペットを削除。確認時にも管理権限と個体IDを検証 |
| `/pet price item: amount:` | ショップ単価。0を明示設定した場合だけ無料 |
| `/pet config key: value:` | 下記の育成数値・必要経験値・倍率・上限を設定 |
| `/pet species rarity: names:` | 種類を「、」区切りで設定（1～25種、各40文字以内）。既存の個体は変更しない |
| `/pet reward user: reference: item: quantity:` | 管理者がイベント報酬・クエスト達成を登録し卵・エサ・おもちゃ・経験値を付与 |

報酬の`reference`は、イベント・クエストの達成を識別する管理用の記録IDです。同じサーバー・対象者・記録IDでは重複付与しません。別の報酬を追加する場合は別の記録IDを使ってください。経験値報酬には設定済みの経験値倍率を適用し、対象者にペットがいない場合は未配布としてエラーにします。既存のボス・ゾンビなどへ自動的に報酬を追加する変更はありません。

### 管理者が設定する数値

`/pet config` の `key` 選択肢に説明が表示されます。

| key | 意味 |
|---|---|
| `xp_base` | 次レベルの必要経験値＝この値×現在レベル |
| `xp_multiplier` | 獲得経験値の倍率（0～100、小数可、端数切り捨て） |
| `level_cap` | レベル上限（1～100、未設定時100） |
| `message_xp` / `message_interval` | メッセージ1件の基礎経験値／獲得間隔の秒数 |
| `vc_xp` / `vc_interval` | VCの基礎経験値／獲得間隔の秒数 |
| `hunger_interval` / `hunger_loss` | 満腹度が減る間隔の秒数／1間隔で減る量 |
| `feed_hunger` / `feed_xp` / `feed_bond` | エサ1個による満腹度・基礎経験値・親密度 |
| `pet_bond` | 撫でたときの親密度 |
| `play_xp` / `play_bond` | 遊んだときの基礎経験値・親密度 |
| `toy_price` | おもちゃの単価（`/pet price item:おもちゃ` でも変更可能） |
| `feed_neglect_interval` / `play_neglect_interval` | エサ／遊び不足で弱るまでの秒数（各1以上） |
| `vet_price` / `vet_hunger` | 獣医の治療費／治療による満腹度回復 |

必要経験値の基準と時間間隔は1以上の整数です。親密度・満腹度の増減設定は0～100、育成後の値も0～100です。満腹度0は「空腹」表示のみで、死亡や能力低下はありません。時間経過は取得時に計算し、Bot停止中も満腹度は減ります。設定を変える時点まで旧設定で精算するため、新設定を過去へ遡って適用しません。

### ショップパネル

管理者が `/pet panel` で設置します。ノーマル卵・レア卵・エサ・おもちゃの4ボタンから、購入者本人だけに1個分の確認画面を開きます。購入者ごとに別の確認となり、他の人の購入や公開パネルを無効にしません。ボタンを押した段階では引き落としません。

パネルを設置し直さなくても、確認画面で最新の管理者設定価格を読み直します。価格未設定・ノーマル種未登録なら購入を停止します。まとめ買いは `/pet buy` を使用します。

### 弱った状態と獣医

- エサ、遊びの**どちらか一方**が管理者指定の時間以上行われていないと弱ります。各行動の最終実行時刻、未実行なら誕生日から判定します。未設定の条件に任意の期限は入れません。
- 弱っていても飼い主の通常のお世話は可能ですが、弱り状態そのものを解除できるのは獣医の治療だけです。死亡・消失・能力低下は追加していません。
- `/pet info` に健康状態と原因を表示します。時間条件は情報取得・お世話・VC観測などの処理時に判定・保存します。自動DMや通報通知は送りません。
- **`/pet treat user:飼い主` は「獣医」ロール所持者だけ**が実行できます。Administratorだけでは代用できません。「獣医」ロールが重複している場合は治療を停止します。
- 獣医が治療を提案すると、チャンネルに治療費・満腹度回復量を記載したカードを投稿します。飼い主だけが2分以内に支払いを承認できます。提案時点では無課金です。
- 承認時に、飼い主・サーバー・個体ID・未治療状態・最新の料金／回復量・有効期限を検証し、提案した獣医のロールも再取得します。ロール剥奪・設定変更・ペットの入れ替え・残高不足では引き落としません。
- 治療費は飼い主の銀行共有残高からシステムへ支払います。獣医への送金は行いません。価格は未設定なら治療停止、明示的に0を設定した場合だけ無料です。
- 治療・支払い・記録は同一トランザクションです。連打・同時承認・別の獣医からの複数提案でも、同じ弱りに対して二重に請求しません。飼い主のキャンセルも保存します。
- 治療で弱り状態を解除し、設定量だけ満腹度を回復します。治療時刻から各お世話期限を再開しますが、実際のエサ・遊び履歴は捏造せず維持します。お世話不足が続けば再度弱ります。
- 先にエサ・遊びの育成設定、価格、治療費・回復量を設定してから、弱るまでの時間を設定してください。弱り条件を有効化すると既存個体も誕生日／実際の最終お世話時刻から判定します。

### VC・メッセージ経験値

- サーバー内のBot・Webhook以外のメッセージを対象に、設定した獲得間隔で付与します。本文の読み取り・保存はしません。追加するGateway Intentは`GuildMessages`のみで、`MessageContent`は不要です。
- VC経験値は全VC・ステージVC（Hub生成先を含む）で、Botが接続中に観測した時間にだけ付与します。VC記録のサーバー別／全体オプトアウトを尊重します。
- VC退出直前の観測を精算します。獲得間隔に満たない観測済みの時間は在庫データに保持し、移動・再入室・再起動でも引き継ぎます。
- 切断・停止時間や90秒超の観測欠落は推定加算しません。接続復旧後から観測を再開します。
- 孵化前の活動は遡って経験値にしません。ペットを手放すとその個体の経験値と活動の途中経過も破棄します。

## 保存・公開

`pet_settings`・`pet_accounts`・`pet_actions`・`pet_treatment_requests`で設定、個体、在庫、日次回数、健康状態、お世話日時、活動の最終観測、治療提案・操作記録をPostgreSQLに保存します。個体IDはUUID、オーナーとサーバーはアカウント主キーです。同時操作もアカウントごとのロックで直列化します。

開発DBに4テーブルを用意しています。本番へは通常の再公開でスキーマを適用してください。起動時DDLや本番マイグレーション用スクリプトは追加していません。多機能Bot起動時に `/pet` のグローバル定義だけを個別更新し、他のコマンドとギルド専用コマンドは置換しません。本番と同じトークンで開発Botを二重起動していません。
