# 懸賞金PvP・武器公開カード

## 武器の表示

多機能Botの `/武器選択` の成功時と、`/強化` の支払い確定後に、操作したチャンネルへ公開Embedカードを投稿する。
表示するのはユーザー・武器名・Lv・固有スキル・強化の成否・消費費用。内部攻撃力・防御力・決済後残高は公開しない。
支払い確認、キャンセル、エラー、管理者の内部確認は非公開を維持する。
失敗した強化もカードに表示するが、従来どおり費用は消費し、Lv低下・破壊はない。

公開カードは決済と同じトランザクションで送信待ちとして保存する。Discord送信失敗時は15秒以上のバックオフで再試行し、
再起動しても未送信カードを失わない。送信中の同時処理は行ロック、短時間のDiscord応答喪失は安定したnonceで重複を抑制する。
Discordのnonce重複排除期間を超える「送信成功・応答喪失」まで完全な一回送信を保証するものではない。
Botに閲覧・送信・EmbedLinks権限がない場合は、選択・強化の決済前に停止する。

## 対戦コマンド

```
/pvp 募集 相手:@相手 賞金:10000 制限分:30
/pvp 情報
/pvp 攻撃
/pvp 回復
/pvp 取消
/pvp 降参 確認:True
```

相手指定の1対1。**募集者本人が戦い、賞金は募集者だけが負担する。**
両者は本船員・武器所持者・参加時所持金1以上が必要。管理者でも本船員を省略できない。
Bot、自分自身とは対戦不可。PvPは1サーバー内で1人1件までで、受付中の相手も予約する。
本船員の判定は既存の鍛冶屋と同じ。戦闘操作時に更新し、承諾時には募集者も再確認する。
本船員を失った場合も取り消し・辞退・降参は可能。

### 賞金

- 募集時に募集者の銀行残高から賞金を預かる。相手から賭け金は取らない。
- 相手の承諾期限は2分。承諾した時点から戦闘制限時間を数える。
- 相手の勝利：相手へ賞金を加算。
- 募集者の勝利：募集者へ賞金を返却。通貨を新たに発行しない。
- 承諾前の取り消し・辞退・未成立・戦闘時間切れ：募集者へ全額返却。
- 開始後の取り消しは不可。降参は相手の勝利となる。ボタンには非公開の最終確認を挟む。
- 制限分は1～180分、省略時30分。時間切れはHP差にかかわらず引き分け。
- 賞金の預かり、勝敗、残高、取引記録、予約解除、公開カード保存はトランザクションで整合させる。
- 同一操作や同時操作で二重攻撃・二重支払いしない。決済失敗で勝利だけが確定することはない。
- 受取口座の残高上限で精算できない場合は未精算状態を維持し、管理者の残高調整後に再試行する。
- DBに期限を保存し、15秒周期・各操作の前に期限を再評価する。Bot停止中の期限は復旧後に精算する。

### HPと戦闘

- 募集者の最大HPは**賞金を預ける直前の所持金**、相手は承諾時の所持金で固定。賞金預かりだけで募集者を不利にしない。
- 被ダメージで銀行残高は減らず、入出金で最大HPを増減させない。
- 攻撃は無料、5秒間隔。両者がリアルタイムに操作する。対戦の相手はプレイヤーなのでボスの自動反撃は行わない。
- ボス戦と同じ武器攻撃計算・Lv補正・10%の会心判定・1.5倍の会心・武器別連続攻撃を使用する。
- 相手の武器防御力を適用。イベント固有の「補正ロール」はPvPには適用しない（倍率1）。
- 武器ごと20種の攻撃文を共用し、同じ文が連続しない。会心・コンボ・フィニッシュ・オーバーキルを表示する。
- 3回目ごとの固有スキルも適用。槍は次の攻撃を半減、弓は防御を無視、杖は自分を最大HPの20%回復する。
- 武器強化は同じ武器の次の攻撃から反映。武器種類・防御・最大HPは参加時固定。
- `/pvp 回復` は有料、最大HPの10%（切り捨て・最低1・最大HPまで）、30秒間隔。攻撃とは独立。
- 回復料金は既存のボス回復料金を募集時に固定する。未設定なら回復のみ不可。無料回復にはしない。
- 満タン・残高不足・クールタイム中は課金しない。
- ボス用の `/攻撃`・`/回復` と区別するため、PvPでは `/pvp` またはPvP専用ボタンを使う。

対戦募集、攻撃・回復の結果、勝敗・返却は募集したチャンネルに公開カードで表示する。
公開済みの古いカードのボタンでも現在のDB状態で検証するため、終了済み・第三者の操作は拒否する。
送信元チャンネル削除・権限変更で表示できない場合も、銀行の決済記録は消さない。

## 適用と検証

新しいテーブル定義は `lib/db/src/schema/pvp.ts`。開発DBに追加済み。公開DBはReplitの再公開時のスキーマ適用を使い、
起動時のDDLや独自の本番移行処理は追加しない。多機能Bot起動時に `/pvp` を個別登録し、既存のコマンドを一括置換しない。
Discord接続を伴うBotの開発起動は、本番との二重稼働を避けるため実施しない。

```
pnpm run typecheck:libs
pnpm --filter @workspace/community-bot run typecheck
RUN_PVP_DB_TESTS=1 pnpm --filter @workspace/community-bot exec vitest run src/__tests__/pvp-db.test.ts src/__tests__/pvp-rules.test.ts src/__tests__/pvp-interaction.test.ts
```

DBテストは開発DBのランダムなテスト用サーバーIDだけを使用し、終了後に削除する。本物のDiscordメンバーの残高には触れない。
