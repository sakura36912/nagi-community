# キミノヒトミニKPshop チケット用パネル

## 初期設定

`/shop ticket-panel` の設置は「夜鴉」「黒兵」のいずれかのロール所持者、またはAdministrator権限を持つ管理者が実行可能。
実行時に本人の最新ロール・管理者権限を確認する。役職名は完全一致で、黒真珠・白真珠などのキャストロールのみでは設置できない。
Discordではサブコマンドごとの既定権限を指定できないため、`/shop` 全体の管理者限定表示を解除し、
Bot内で `ticket-panel` 以外のショップ操作を管理者限定にする。料金設定・商品管理の権限は夜鴉・黒兵へ委譲しない。
設置済みパネルの注文・追加注文・明細集計の利用条件は変更しない。

1. `/shop add` のカテゴリで **キミノヒトミニKPshop** を選び、ドリンク名と単価を登録する。
   - チケットのドリンク一覧は、特殊効果と付与ロールがない通常商品のみを使用する。
   - 他のショップの商品は混ぜない。
2. チケットのテキストチャンネルまたはスレッドで `/shop ticket-panel` を実行する。
   - 既定では「黒真珠」「白真珠」という名前のロールを検索する。
   - 名前が重複している場合などは `black_role` と `white_role` で明示指定する。
   - どちらか一方のロールを持つ人が指名候補になる。Botは除外する。
   - 複数チケットに設置可能。購入ログは操作したパネルのチケットに表示する。
3. VIP・延長料金は後から `/shop ticket-prices` で設定する。

## 料金を後から決める

- `/shop ticket-prices`：現在の設定を確認
- `/shop ticket-prices vip:500`：VIP料金だけを変更（数値は例）
- `/shop ticket-prices extension:200`：延長1回分だけを変更（数値は例）
- `/shop ticket-prices unset:両方`：両方を未設定に戻す

料金の初期値は「未設定」。0（明示的な無料）とは別の状態。
未設定の希望を「希望する」にして支払いを進めることはできない。
「希望しない」なら、その追加料金は発生しない。
VIP・延長の料金は注文1件にそれぞれ1回だけ加算し、ドリンクの個数では乗算しない。
料金は同じサーバーのチケット用パネルで共通。
VIP・延長は希望の記録と追加料金の決済であり、VCの自動延長やVIPロールの自動付与ではない。

## 購入の流れ

「注文する」→ 指名キャスト → VIP希望 → 延長希望 → ドリンク名 → 数量（1〜25）→ 合計確認 → 支払い確定。

- 選択画面は本人だけに表示し、他の人・別チケットからの操作は拒否する。
- 確定前は引き落とさない。キャンセル・最初からの選び直しが可能。
- キャスト・ドリンクが25件を超える場合も、ページを切り替えて全候補を選べる。
- 注文操作は20分で期限切れ。Bot再起動後も、期限内の保存済み注文を継続できる。
- 確定時に商品・料金・対象キャストを確認し直す。
- 金額が変更された場合は、引き落とさず新しい金額を表示して再確認を求める。
- 引き落とし・在庫追加・取引履歴・支払済み状態を同一DBトランザクションで保存する。
- 同じ注文の確定を繰り返しても二重決済しない。別注文の同時購入でも残高を超えて使えない。

## チケット内の購入ログ

購入者、指名キャスト、VIP希望と料金、延長希望と料金、ドリンク名、単価、数量、合計金額、注文ID、支払日時を表示する。
メンション表記による通知は行わない。

Botにはチケットの閲覧・送信・埋め込み権限が必要。スレッドの場合はスレッド内送信権限も必要。
権限不足やアーカイブ済み・ロック済みスレッドでは支払いを開始しない。
決済後にログ送信だけが失敗した場合、決済は取り消さず、本人の画面に「ログを再送（再決済なし）」を表示する。
支払い済みの確認操作も結果確認・ログ再送として扱い、再度引き落とさない。

## データベースと本番反映

既存のPostgreSQLを使用し、残高や既存ショップの商品は移行・変更しない。
新しいチケット用テーブルは、この機能の初回操作時に追加作成する。
明示的に準備する場合の移行スクリプトは `lib/db/migrate-kp-ticket.ts`。
管理コマンドの利用開始には新しいコードの公開が必要。`/shop` はBot起動時の個別同期で更新される。
開発ワークフローで同じBotを同時起動しない。

DB連携テストは `RUN_KP_TICKET_DB_TESTS=1` を指定して
`pnpm --filter @workspace/discord-bot exec vitest run src/__tests__/kp-ticket-db.test.ts` で実行する。
開発DBに識別用のテスト行だけを作成し、終了時に削除する。
