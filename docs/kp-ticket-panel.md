# KP島の利用顧客記録

`/shop customers` はパネル設置とは独立した顧客確認コマンドです。
管理者（Administrator）・夜鴉・黒兵のみ利用でき、結果・添付明細は実行者だけに表示します。

- `/shop customers`：顧客別の利用チケット数、注文数、累計支払額、最終支払い日時。
- `/shop customers user:@ユーザー`：その顧客の利用履歴、担当キャスト、商品・数量、支払額、日時、チケットID。
- `page`：一覧・履歴のページ。添付テキストには指定顧客または顧客一覧の全件を出力します。

記録元はKPチケットの支払い済み注文です。別の顧客台帳へ複製せず、支払い完了と同時に履歴へ反映されます。
保存済みの過去注文・削除済みチケットも含む全期間集計で、営業日売上集計とは異なり18:00〜翌10:00のフィルターは適用しません。
チケット数は顧客ごとにチャンネルIDの重複を除外し、追加注文は注文数だけを増やします。
注文前の単なる入室、未払い・キャンセルは利用記録に含みません。日時は日本時間です。
既存のパネル・購入・残高処理は変更せず、新たな課金やDB移行はありません。

# キミノヒトミニKPshop チケット用パネル

## 初期設定

`/shop ticket-panel` の設置は「夜鴉」「黒兵」のいずれかのロール所持者、またはAdministrator権限を持つ管理者が実行可能。
実行時に本人の最新ロール・管理者権限を確認する。役職名は完全一致で、黒真珠・白真珠などのキャストロールのみでは設置できない。
Discordではサブコマンドごとの既定権限を指定できないため、`/shop` 全体の管理者限定表示を解除し、
Bot内で `ticket-panel` 以外のショップ操作を管理者限定にする。料金設定・商品管理の権限は夜鴉・黒兵へ委譲しない。
設置済みパネルの注文・追加注文・明細集計の利用条件は変更しない。

1. `/shop add` のカテゴリで **キミノヒトミニKPshop** を選び、ドリンク名と単価を登録する。
   - チケットのドリンク一覧は、特殊効果と付与ロールがない通常商品のみを使用する。
   - 他のショップの商品は混ぜない。
2. Ticket Toolが作成したチケット本体（例：`ticket-0219` のテキストチャンネル）で `/shop ticket-panel` を実行する。スレッド作成は不要。
   - 既定では「黒真珠」「白真珠」という名前のロールを検索する。
   - 名前が重複している場合などは `black_role` と `white_role` で明示指定する。
   - どちらか一方のロールを持つ人が指名候補になる。Botは除外する。
   - 複数チケットに設置可能。購入ログは操作したパネルのチケットに表示する。
3. キャスト追加のため、通貨Botにそのチケットの閲覧・ロールの管理権限を付与する。Botは指名キャスト個人に、そのチケットだけの閲覧・送信・履歴閲覧を許可する。ロール全員や他のチケットの権限は変更しない。

## VIP・延長の受付終了

通常注文・追加注文ともVIP・延長の選択はなく、ドリンク代のみを支払う。
旧 `ticket-prices` の設定値が保存されていても新しい注文には加算しない。
古い未決済注文にVIP・延長が含まれる場合は請求せず、選び直しを案内する。
支払い済みの過去明細・料金設定データは削除しない。

## 購入の流れ

「注文する」→ 指名キャスト → ドリンク名 → 数量（1〜25）→ 合計確認 → 支払い確定。
「追加注文」では同じ本人・チケットの最後の支払い済みキャストを固定し、ドリンク選択から開始する。

- 選択画面は本人だけに表示し、他の人・別チケットからの操作は拒否する。
- 確定前は引き落とさない。キャンセル・最初からの選び直しが可能。
- キャスト・ドリンクが25件を超える場合も、ページを切り替えて全候補を選べる。
- キャスト選択時（支払い前）に、指名した本人だけに同じチケットの閲覧・送信・履歴閲覧を許可する。既存の個別設定には必要な3権限のみをマージする。
- カテゴリ・ロール全体・他のチケットの権限は変更しない。既に本人が必要な権限を持っていれば編集しない。
- 既存スレッドでの利用も維持する。その場合はスレッドの参加者追加だけを行い、親の権限が不足していれば管理者への設定依頼を案内して停止する。
- キャスト追加に失敗したら選択を進めず、料金も引き落とさない。設定修正後に再選択できる。
- 指名を選び直したり注文をキャンセルしても、追加済みキャストのアクセスは自動削除しない。
- 追加注文では固定キャストのアクセスを確認・追加し、支払い直前にもアクセス追加を再実行する。失敗した場合は決済しない。
- 注文操作は20分で期限切れ。Bot再起動後も、期限内の保存済み注文を継続できる。
- 確定時に商品・料金・対象キャストを確認し直す。
- 金額が変更された場合は、引き落とさず新しい金額を表示して再確認を求める。
- 引き落とし・在庫追加・取引履歴・支払済み状態を同一DBトランザクションで保存する。
- 同じ注文の確定を繰り返しても二重決済しない。別注文の同時購入でも残高を超えて使えない。

## チケット内の購入ログ

購入者、指名キャスト、ドリンク名、単価、数量、合計金額、注文ID、支払日時を表示する。過去の支払い済みVIP・延長付き注文の再送ログは当時の内訳を保持する。
メンション表記による通知は行わない。

Botにはチケットの閲覧・送信・埋め込み権限が必要。スレッドの場合はスレッド内送信権限も必要。
権限不足やアーカイブ済み・ロック済みスレッドでは支払いを開始しない。
決済後にログ送信だけが失敗した場合、決済は取り消さず、本人の画面に「ログを再送（再決済なし）」を表示する。
支払い済みの確認操作も結果確認・ログ再送として扱い、再度引き落とさない。

## データベースと本番反映

### 明細の集計

- 「明細を集計」：夜鴉・黒兵・Administratorのみ使用可能。今のチケット内の支払い済み注文を集計し、チケット内へ表示する。
- 両集計ボタンとも押すたびに最新のメンバー権限を確認し、権限を失った人や確認できない人は集計できない。ボタン自体は他の人にも表示されるが、対象外の操作は拒否する。注文・追加注文の利用権限は変更しない。
- 「全チケットを集計」：同じサーバーの全チケット（削除済みを含む）の売上を、日本時間の18:00〜翌日10:00の営業日ごとに合算する。夜鴉・黒兵・Administratorのみ使用可能で、結果は操作した本人にだけ表示する。
- 期間は支払い完了日時で判定する。18:00ちょうどを含み、翌10:00ちょうどを含めない。10:00〜18:00の支払いはこの営業日集計の対象外。
- 初期表示は直近の18:00開始の営業日。深夜・午前中・10:00〜18:00は前日開始分を表示する。営業中は集計操作時点までの暫定売上になる。
- 結果の「営業日を指定」から `YYYY-MM-DD` 形式の営業開始日を入力できる。例：`2026-11-08` は11月8日18:00〜11月9日10:00。送信時にも最新のスタッフ権限を再確認する。
- 現存チャンネルの一覧は使わずDBの支払い済み記録から集計するため、チケット削除後も集計できる。保存されていない過去注文は復元できない。現在のチケット単位の「明細を集計」は従来どおり全期間。
- 「全チケットを集計」で、全チケットの合計・注文明細と、キャスト別の売上合計を両方表示する。同じ営業日の支払い記録を使い、追加注文も合算する。添付の `kp-all-tickets-statement.txt` に全明細、`kp-cast-sales.txt` に全キャストの売上合計を出す。キャスト別の欄は件数・商品内訳を出さず、キャスト未記録分は別枠で残す。過去のVIP・延長付き注文も当時の支払い総額を維持する。他サーバー・未払い・キャンセルは含めず、再決済もしない。
- 過去の支払い済み記録も対象にするが、通常のKPshop購入など、チケット注文として保存されていない取引は含めない。
- 既存パネルのボタンは自動更新しない。再公開後 `/shop ticket-panel` を実行して新しいパネルを設置すると、全チケット集計ボタンが付く。
- 既に「全チケットを集計」ボタンがあるパネルは、再公開後そのまま営業日集計を利用できる。チケットがすべて削除された場合は、スタッフが操作できる別のテキストチャンネルにパネルを設置して利用する。
- スレッドからチケット本体へ設置場所を変える場合は、チケット本体で新たに設置する。過去のスレッド注文は別チャンネルの記録として保持し、自動移動・合算しない。全チケット集計では両方を確認できる。

既存のPostgreSQLを使用し、残高や既存ショップの商品は移行・変更しない。
新しいチケット用テーブルは、この機能の初回操作時に追加作成する。
明示的に準備する場合の移行スクリプトは `lib/db/migrate-kp-ticket.ts`。
管理コマンドの利用開始には新しいコードの公開が必要。`/shop` はBot起動時の個別同期で更新される。
開発ワークフローで同じBotを同時起動しない。

DB連携テストは `RUN_KP_TICKET_DB_TESTS=1` を指定して
`pnpm --filter @workspace/discord-bot exec vitest run src/__tests__/kp-ticket-db.test.ts` で実行する。
開発DBに識別用のテスト行だけを作成し、終了時に削除する。
