Discordサーバー「凪-Nagi-」内で使用する
「裏募集システム」を作成したいです。

目的は、サーバー内で
・1対1の個通募集
・寝落ち募集
を安全に行えるようにすることです。

以下の仕様をもとに設計・実装してください。

# 1. 募集種類

募集は2種類です。

・🎙️ 個通募集
・🌙 寝落ち募集

募集者は専用パネルから、どちらかを選択して募集を開始します。

［🎙️ 個通募集］
［🌙 寝落ち募集］

# 2. 募集開始

募集種類を選択したら、モーダルなどを使用して
「一言」を入力できるようにしてください。

年齢の入力欄は必要ありません。

入力完了後、指定した募集チャンネルへ
BOTが募集カードを投稿してください。

# 3. 募集投稿

表示例：

【🎙️ 個通募集】

名前：さくら
一言：暇なので話しましょ！

募集開始：○時○分

［申請する］
［募集終了］

可能であれば、
募集者のDiscordアイコンもEmbedに表示してください。

募集カードに表示する情報は、

・募集種類
・募集者名
・募集者のDiscordアイコン
・一言
・募集開始時刻

とします。

※年齢は取得・入力・表示しない仕様にしてください。

# 4. 申請システム

募集投稿の
［申請する］
ボタンを押すと、その募集へ申請できるようにしてください。

申請時には必要に応じてモーダルを表示し、
申請者も「一言」を入力できるようにしてください。

募集者が確認できる申請者情報は、

・申請者名
・Discordアイコン
・一言

のみとします。

年齢情報は取得・入力・表示しないでください。

申請者の情報は募集者だけが確認できるようにしてください。

他の利用者から、

・誰が申請しているか
・何人が申請しているか
・誰が選ばれたか

などの詳細情報は見えないようにしてください。

# 5. 同じ募集への重複申請

同じ利用者が同じ募集へ何度も申請できないようにしてください。

既に申請している場合は、

「既にこの募集へ申請しています。」

と本人だけに表示してください。

必要であれば
［申請を取り消す］
機能も用意してください。

# 6. 募集者への申請通知

申請が届いたら、
募集者だけが申請者を確認できるようにしてください。

表示例：

【📨 申請が届きました】

名前：〇〇
一言：よかったら話しましょ！

［この人を選ぶ］
［見送る］

Discordアイコンも表示してください。

複数人から申請が届いた場合は、
申請者一覧をセレクトメニュー等で確認できるようにしてください。

# 7. 募集者が相手を選択

完全ランダムマッチングではありません。

募集者自身が、
届いた申請者の中から話したい相手を1人選択する方式です。

募集者は、

［この人を選ぶ］
［見送る］

などの操作を行えるようにしてください。

複数人から申請が来ている場合でも、
最終的に募集者が1人を選択します。

# 8. 見送りについて

募集者が［見送る］を押した場合、
申請者本人へ直接、

「この募集は終了しました。」
「見送られました。」

などの通知は送らないでください。

また、

・不採用
・落選
・拒否された

など、相手を傷つける可能性がある表現は使用しないでください。

見送り情報は募集者本人と管理ログのみで扱ってください。

# 9. マッチ成立

募集者が
［この人を選ぶ］
を押したらマッチ成立です。

成立後は自動で、

・募集を終了
・新規申請を停止
・募集投稿を成立済み状態へ変更
・選ばれた相手へ通知
・2人専用VCを作成

してください。

募集投稿は例えば、

【🔒 募集終了】

のように変更し、
［申請する］ボタンを無効化してください。

# 10. 選ばれなかった申請者

募集者が1人を選択して募集が成立した場合、
他の申請者には、

「この募集は終了しました。
また別の募集をご利用ください。」

程度の通知を送ってください。

誰が選ばれたかは表示しないでください。

「落選」「不採用」などの表現は禁止します。

# 11. 専用VC

マッチ成立後、
2人専用のVCを自動作成してください。

VC名例：

🎙️｜裏航海-001
🌙｜裏航海-002

VCへアクセスできるのは、

・募集者
・選ばれた申請者
・BOT
・必要な管理者

のみとします。

その他の一般メンバーは、

・接続
・発言

ができないようにしてください。

必要に応じて、
VC自体を一般メンバーから非表示にする設計でも構いません。

# 12. VC自動削除

専用VCから2人とも退出した場合、
3分後にVCを自動削除してください。

3分以内にどちらか1人でもVCへ戻った場合は、
削除タイマーをキャンセルしてください。

再度2人とも退出した場合は、
改めて3分タイマーを開始してください。

管理者が手動でVCを強制削除できる機能も用意してください。

# 13. 募集キャンセル

募集者はマッチ成立前であれば、
自分の募集をキャンセルできるようにしてください。

募集キャンセル時は、

・募集を終了
・新規申請を停止
・募集投稿を終了状態へ変更
・申請者へ募集終了を通知

してください。

申請者への通知は、

「募集者により募集が終了されました。」

程度にしてください。

# 14. ブロック機能

利用者同士でブロックできる機能を作ってください。

片方が相手をブロックしている場合、

・相手の募集へ申請できない
・相手から自分の募集へ申請できない
・マッチ成立できない

ようにしてください。

ブロックされた側には、

「〇〇さんからブロックされています。」

など、
誰からブロックされているか分かる通知は絶対に表示しないでください。

申請できない場合も、

「この募集には申請できません。」

などの一般的な表示にしてください。

# 15. 通報機能

マッチ成立後、
利用者が相手を通報できる機能を用意してください。

例えば、

［🚨 通報する］

からモーダルを開きます。

通報時には、

・通報理由
・詳細、自由記入

を入力できるようにしてください。

管理用チャンネルへ、

・通報者
・通報された相手
・募集種類
・マッチ日時
・VC
・通報理由
・詳細
・マッチID

を送信してください。

通報された側には通知しないでください。

# 16. 対人トラブル対策

以下の行為は禁止事項として扱います。

・暴言
・誹謗中傷
・過度な下ネタ
・セクハラ
・嫌がっていることを続ける行為
・個人情報の過度な詮索
・強引な個人DMへの誘導
・強引な外部通話への誘導
・その他、凪のサーバールールに違反する行為

利用者は、
マッチ成立後でもいつでもVCから退出できるようにしてください。

通常の途中退出には原則ペナルティを付けません。

「相手と合わなかった」
という理由でも退出可能とします。

# 17. 申請荒らし対策

以下の荒らし対策を入れてください。

・同じ募集への重複申請禁止
・短時間での大量申請を制限
・短時間での大量募集を制限
・BOTボタンの連打対策
・終了済み募集への申請防止
・自分自身の募集への申請防止

必要に応じてクールダウンを設定してください。

# 18. 悪質利用への対応

以下のような行為が繰り返される場合、
管理者が裏募集システムの利用を一時停止できるようにしてください。

・募集とキャンセルの大量繰り返し
・申請荒らし
・成立直後の悪質なキャンセルの繰り返し
・通報対象となる行為
・その他、運営妨害

利用停止はDiscordサーバー全体ではなく、
「裏募集システムのみ利用不可」
にできるようにしてください。

# 19. 管理者機能

管理者向けに最低限、
以下の機能を用意してください。

・現在の募集一覧
・現在の申請状況
・現在の成立VC一覧
・募集履歴
・マッチ履歴
・キャンセル履歴
・通報履歴
・ブロック関連の確認
・利用停止
・利用停止解除
・募集強制終了
・マッチ強制解除
・VC強制削除
・裏募集システムON/OFF

管理操作についてもログを残してください。

# 20. ログ

最低限、
以下の情報を記録してください。

・募集開始
・募集終了
・募集キャンセル
・申請
・申請取り消し
・見送り
・マッチ成立
・募集者
・選択された申請者
・募集種類
・募集開始日時
・マッチ成立日時
・VC作成
・VC削除
・ブロック
・ブロック解除
・通報
・利用停止
・利用停止解除
・管理者操作

ユーザー向けの公開ログと、
管理者のみ閲覧できる内部ログは必要に応じて分けてください。

# 21. データ保存

BOT再起動後も必要な情報が消えないようにしてください。

SQLite等の永続DBを使用してください。

保存対象：

・募集情報
・申請情報
・マッチ情報
・ブロック情報
・利用停止情報
・募集履歴
・マッチ履歴
・キャンセル履歴
・通報履歴
・作成VC情報

BOT再起動時には、
Discord側の状態とDBの状態を照合してください。

例えば、

・DBにはVCがあるがDiscordには存在しない
・終了済み募集が募集中になっている
・削除済み募集のボタンが有効
・存在しないユーザー情報が残っている

などを確認し、
可能な範囲で自動修復してください。

# 22. UI

できる限りスラッシュコマンドだけに頼らず、

・Embed
・ボタン
・モーダル
・セレクトメニュー

を使用して、
スマホからでも直感的に操作できるUIにしてください。

想定UI：

【募集パネル】
［🎙️ 個通募集］
［🌙 寝落ち募集］

【募集カード】
［📨 申請する］
［❌ 募集終了］

【募集者専用】
［👥 申請者一覧］
［✅ この人を選ぶ］
［↩️ 見送る］

【成立後】
［🚫 ブロック］
［🚨 通報］

# 23. 同時募集について

1人の利用者が、
同時に複数の募集を出せないようにしてください。

個通募集を出している場合は、
寝落ち募集を同時に出せません。

寝落ち募集を出している場合も、
個通募集を同時に出せません。

また、自分が募集を出している状態で
他人の募集へ申請できるかどうかは、
実装前に確認してください。

勝手に仕様を決めないでください。

# 24. マッチ中の制限

既に裏募集でマッチして専用VCが作成されている利用者は、

・新しい募集を出す
・他の募集へ申請する
・別のマッチを成立させる

ことができないようにしてください。

現在のマッチが終了してから、
再度利用できるようにしてください。

# 25. プライバシー

一般利用者には必要以上の情報を公開しないでください。

特に、

・申請者一覧
・誰が見送られたか
・ブロック関係
・通報内容
・過去のマッチ履歴
・管理者による対応内容

などは公開しないでください。

募集投稿には、
募集に必要な最低限の情報だけ表示してください。

年齢情報は一切扱わないでください。

# 26. 実装前に提示してほしい内容

いきなりコードを書かないでください。

まず以下を整理して提示してください。

1. 機能一覧
2. 利用者側の操作フロー
3. 募集者側の操作フロー
4. 申請者側の操作フロー
5. 管理者側の操作フロー
6. DB設計
7. コマンド一覧
8. ボタン一覧
9. モーダル一覧
10. セレクトメニュー一覧
11. VC権限設計
12. 募集・申請・マッチの状態管理方法
13. BOT再起動時の復旧方法
14. エラー・例外処理
15. 荒らし・対人トラブル対策
16. 実装手順

仕様上判断が必要な部分や、
Discordの仕様上そのまま実装できない部分がある場合は、
勝手に代替仕様を決めないでください。

まず質問・提案を出して、
こちらの確認を取ってから実装してください。

最終的なシステムの基本フローは、

募集を出す
↓
申請者が集まる
↓
募集者だけが申請者を確認
↓
募集者が1人を選択
↓
マッチ成立
↓
2人専用VCを自動作成
↓
個通・寝落ち
↓
2人退出
↓
3分後にVC自動削除

としてください。
